# modules — 一个进程里的内部模块,不是微服务

这个目录以前叫 `services/`。里面有 17 个子目录,**没有一个是 service**:
没有 HTTP server、没有独立进程、没有网络边界。它们全部由同一个 FastAPI 应用
(`apps/api/main.py`)直接 import。

改名是因为**名字在撒谎,而撒谎有代价**:

- `services/` 这个命名暗示了 17 条边界。既然它们不是真边界,就没有任何一条被强制,
  于是模块之间可以随意互相 import —— 得到的是微服务的维护成本和单体的耦合。
- 它也误导了取舍。2026 年的行业共识是"majestic monolith + 抽出真正需要独立的热点路径";
  42% 上过微服务的组织正在往回合并。单人项目上微服务是纯粹的负担,而这个项目
  从来没真的上过 —— 只是穿了那身衣服。

## 目录约定

- 一个模块可以 import `libs/`,**不应该** import 另一个 `modules/` 兄弟模块。
  需要共享的东西提到 `libs/` 去。这是目前唯一的边界规则,也是唯一值得有的那条。
- 需要真正独立成进程的,才配拆出去 —— 判据是"它有独立的伸缩需求或故障域",
  不是"它听起来像一个服务"。

零引用的模块在 `attic/services/`(`ai_orchestrator`、`api_server`、`trading_engine`)。
