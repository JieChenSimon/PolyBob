# PB-0040 组合层真实回放审计（2026-08-25）

## 结论

组合层当前不能 Promotion。已有 `data/multi_asset_portfolio_us_capped.json` 确实由
`modules.simulation.SimulationService` 生成，并且包含真实 SEC 事件、真实日线、费用和滑点，
但 `full_metrics.equity_curve_degraded=true`，所以系统把 `total_return`、`max_drawdown`
和 `sharpe` 置为 `null`。这是正确的 fail-closed 行为，不是可以用 `realized_pnl`、胜率或
profit factor 替代的“收益证明”。

## 已核对的证据

| 项目 | 结果 |
|---|---:|
| 组合执行内核 | `SimulationService` |
| SEC 事件 | 4,984 个过滤后事件，9,062 个过滤前事件 |
| 美股重放标的 | 2,500 |
| 成交数 / 已平仓 | 3,534 / 2,329 |
| 初始资金 / 终值权益 | 100,000 / 89,335.47 |
| 已实现盈亏 | +1,852.99 |
| 费用 + 滑点 | 641.25 |
| 最大毛敞口 / 毛杠杆 | 59,694.29 / 0.6705 |
| 组合总收益、最大回撤、Sharpe | UNKNOWN（权益曲线 degraded） |

终值权益低于初始资金，而已实现盈亏为正，说明仍有未实现持仓或标记路径不完整；这正是
不能只看已平仓盈亏的原因。该结果也没有通过逐标的年度 50%、完整月度 15%、样本外和
组合风险门禁。

## 根因与修复方向

1. 回放使用不同标的、不同结束日期的日线，并在统一日期轴上推进；持仓若超过
   `max_staleness_seconds` 没有新报价，`SimulationService` 会将权益点标为 degraded。
2. 回放前每次重新扫描 SEC 季度 ZIP；本次实测该路径会使 Python 单进程接近 100% CPU，
   不符合项目“充分利用但不超过约 60%”的资源约束。因此本次运行在完成证据确认后主动中止，
   没有把未完成运行写成成功结果。
3. 下一步必须让组合回放读取已通过 PIT 校验的本地 `insider_filings` 规范化数据，或建立
   一次性、带 manifest 的事件物化缓存；不得每次重新解析 ZIP，也不得绕过 `as_of`。
4. 统一日历回放必须显式处理标的最后可交易日：先以最后有效报价平仓，再记录最终权益点；
   若任一持仓没有可验证标记，整条组合权益曲线必须继续保持 UNKNOWN。

## 证据边界

本报告只记录已存在的真实回放结果和本次可复现的性能观察；没有把正向局部盈亏推广成可赚钱
策略，也没有宣称达到用户设定的收益目标。PB-0040 继续保持 `doing`，直到每个标的和组合
同时拥有非 degraded 的成本后样本外权益曲线、独立性/多重检验、逐月/年度和回撤证据。
