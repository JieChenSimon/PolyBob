# PB-0040 回放资源与数据物化修复（2026-08-25）

本轮发现旧的多资产真实回放在两个阶段会打满单核：SEC Form 345 ZIP 的逐行日期解析/重复规范化落盘，以及逐标的日线回放中的 SQLite 成交/权益写入。

已完成的修复：

- SEC 日期解析改为月份映射，避免每行调用 `datetime.strptime`。
- SEC 解析和本地标的读取使用进程级 CPU 时间节流，数值线程固定为 1。
- 多资产回放优先读取本地已物化的 `INSIDER_FILINGS` PIT 数据；只有本地数据缺失时才走真实 SEC ZIP fallback，避免重复写数据湖。
- 回放节流改为按日期批次让出 CPU，避免每个标的每次 dispatch 都进行固定 sleep。
- 被中断的无效 SQLite 临时文件移入系统废纸篓，不进入策略证据或报告。

验证：相关局部测试 `40 passed`，SEC 日期解析新增测试通过。一次真实多资产运行的临时账本推进到 2025-10-30，但因监测到单次日期处理出现约 94% CPU 峰值而主动停止；该文件未被当作完整策略结果。组合收益结论仍需在进一步的批次级 CPU 限制和进度检查点完成后再登记。
