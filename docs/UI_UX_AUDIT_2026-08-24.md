# PolyBob 前端逐页 UI/UX 与功能审计

日期：2026-08-24  
任务：PB-0026  
审计角色：产品信息架构、金融终端 UI、交互与可访问性、数据可信度、浏览器 QA、性能与运行时

## 审计范围

使用真实运行中的 Dashboard（桌面 1440px、移动 390px）逐页访问核心路由，配合 API 状态、浏览器快照、控制台和生产构建检查。截图落盘于 `apps/dashboard/output/playwright/`；该目录为生成物，不纳入 Git。

覆盖路由：

- 核心工作区：`/overview`、`/markets`
- 资产终端：`/us-equities`、`/a-shares`、`/crypto/altcoin-discovery`、`/crypto/BTC`、`/btc-5m`
- 策略与运行：`/strategies`、`/simulation`、`/execution`、`/risk-ops`
- 系统与辅助：`/settings`、`/journal`、`/dev-control`、`/polymarket`、`/equities`、`/crypto`

## 结论与修复

| 页面/区域 | 发现 | 处理结果 |
| --- | --- | --- |
| Markets | 新闻和全球情绪位于资产工作区之前，用户必须穿过宽泛上下文才能看到市场列表、选中市场和盘口 | 已将资产入口、最佳机会、数据可信度、市场列表/选中市场前置；新闻和情绪保留为支撑证据 |
| Markets 移动端 | 原信息顺序导致首屏过长，核心选择动作不突出 | 已按“选资产 → 看机会 → 看数据可信度 → 看盘口/证据 → 看新闻”的顺序重排 |
| 模拟盘 | 禁用状态下仍请求必然返回 403 的 presets，浏览器控制台把安全阻断显示成错误 | 已仅在 Paper Lab 启用后请求 presets；禁用时明确显示“先启用模拟盘” |
| 模拟盘表单 | 打开新建表单时曾因子组件引用未传入的运行时变量产生 ReferenceError | 已改用显式 `enabled` 属性；打开表单冒烟通过，控制台错误为 0 |
| 执行台/首页待办 | Pair Lab 未启用时，执行状态接口因直接要求可选服务而返回 500，前端出现 CORS 表象错误 | 已返回 200，并增加 `pair_feature_state=unknown`；不把可选能力的缺失伪装为空或阻断整页 |
| 特征引擎 | 单边盘口的 `spread_bps=None` 被拿来与阈值比较，实时事件处理反复抛出 TypeError | 已显式跳过未知价差，并增加回归测试；单边盘口仍保持 UNKNOWN |
| 全局品牌 | 页面元数据和导航副标题仍是泛化的“个人市场工作台” | 已统一为“量化交易工作台 / Quant Trading Workbench” |

## 专业 UI/UX 评价

- 核心决策路径已经从“新闻浏览”转为“资产选择—机会—数据可信度—盘口/策略证据”，更接近专业交易工作台。
- 美股、A 股、加密货币和 BTC 5 分钟终端采用统一的深色资产终端结构：选中标的、行情、图表、盘口、均线、策略实验室在同一上下文内；数据不足时展示 UNKNOWN/blocked，而不是填零。
- 模拟盘使用显眼的 `PAPER ONLY · REAL-DATA DRIVEN` 边界，且真实行情不可用或样本不足时不展示虚构收益，符合量化产品的数据诚信要求。
- 移动端导航可折叠，菜单和中英文切换已实测；核心入口使用纵向卡片，桌面端使用并列工作区。
- 当前仍有可接受的专业终端密度：资产终端在移动端较长，属于信息完整性与首屏简洁之间的取舍；后续可继续做折叠分组和 sticky summary，但不影响当前核心功能。

## 验证结果

- Dashboard：17 个测试文件、74 个测试通过。
- Python 单元回归：`tests/test_degradation_missing_data.py` 14 个测试通过。
- 生产构建：`npm run build` 通过，Next.js 路由生成成功。
- 浏览器：模拟盘状态 API 200；禁用状态打开新建表单、策略目录加载和关闭路径均通过；Overview、Markets、资产终端截图回归无控制台错误。
- 运行时：API 重启后正确加载模拟盘路由；关闭 API 时由系统生命周期完成服务停止，未使用强制 kill 作为应用逻辑。

## 证据边界

本审计验证的是页面信息架构、交互可用性、API 状态呈现和运行时错误，不宣称任何策略已经盈利。策略是否能赚钱仍必须以真实历史数据、成本/滑点、样本外和长期模拟盘账本验证。
